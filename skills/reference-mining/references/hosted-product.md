# The reference is a hosted product, not a repo

The evidence is its public surface. Build original code from a feature map; never copy its code, text, or assets.

- Survey in order: landing page and navigation, the feature pages (form fields, option lists, counts, limits), then the help center and terms, which state limits the UI hides. If a text extractor fails, drive the page in a browser and dump its visible text and links.
- Write the feature map as input -> option -> output rows and mark each built / substituted / not built. Say where a substitute is weaker; a parity claim without those gaps overstates.
- Map each feature onto the target's existing queue, storage, and logging before adding anything new.
- Cut features whose function is the harm (for example nonconsensual imagery of real people) before writing the map, say so in one line, and keep the rest of the scope.
