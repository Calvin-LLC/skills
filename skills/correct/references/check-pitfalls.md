# Check and proof pitfalls

- **Generated map with a `--check` flag.** The generator runs only when someone remembers it, so the map drifts exactly on the files being edited. Wire `--check` into a gate that already runs where the edits land (cron, pre-stage runner), and treat a stale verdict as a FAIL whose fix is regenerate, not a prose reminder next to the generator.
- **Runner and tool in different workspaces.** A stage or gate script resolves its repo from its own path, while the check tool may exist only in a satellite workspace, so the runner calls a tool that is not there (version error, silent 0). Test that the tool's path exists from the runner's resolved root before calling it. When it lives elsewhere, reuse the pattern the repo already has for that split (an env-var root override defaulting to the satellite path, or a forwarder in the runner's scripts directory), not a hard-coded sibling guess. Keep one authority for where the tool lives, and prove the gate fires from the root the runner uses.
- **Git-excluded work tree.** When the tree the work happens in is itself git-excluded, a CI step cannot reach it. Put the runner inside that tree, call it from a local pre-commit hook for the tracked repo around it, and say in the report that the hook is unversioned and runs on this machine only.
- **Docs that cite `file:line`.** They rot as soon as the file moves. Cite function or type names, and add a CI check that fails on any `path:line` citation or untracked path in tracked Markdown, with an error naming the fix. Prove it by putting an old pre-rewrite version of the doc into the tree and counting the findings.
- **Build artifacts in the repo.** A compile step run from the repo root drops object files there on every run, and the clutter looks like the check's output. Build in a temp directory or pass an explicit output path.
- **PowerShell-wrapped checks.** A child's `Write-Error` plus `exit 2` lands as rc=1 at the calling shell. Assert the verdict line and the exit status together.
- **Copy sources.** Notes that agents copy from (source text, talk tracks, archives) are where a retracted claim survives: the live files get corrected and the copy source keeps the old value. Scan them with the common rules, and mark a line that must quote the wrong value on purpose with an exemption token the check honors, so a correction note does not fail its own gate.
- **Encodings.** A pattern written for plain prose is blind to the same fact in another encoding: `86%` is `86\%` in LaTeX source and arrives line-wrapped or ligatured in text extracted from a PDF. Scan the source format and the rendered output, and give each format its own must-fail case. When a rule only matters for outgoing documents, keep a separate, narrower rule set for internal notes so they do not drown the real hits.
- **Over-broad predicates.** A predicate that fires on any `ok=1` substring fails legitimate call sites that check a different component's output. Scope it to lines that inspect the component under discussion, and exempt the one file that must reproduce the bug with an explicit marker and a reason in the same comment.
- **Hand-edited mode switches.** A switch people edit in a shared header (a `#define` that turns security off for development) will eventually ship. Derive it from the build configuration only, add a compile-time `#error` for the forbidden combination whose message says where the switch may be set, and prove it through the real build system: compile one translation unit per configuration and require Release to fail and Debug to pass.
- **A harness that cannot say no.** A compiler handed a header alone prints a warning, does nothing, and exits 0, which reads as "guard silent" in every case, including the one that must fail. Compile a tiny translation unit that includes the header, and require the must-fail case to fire before believing the must-pass cases stayed quiet.

- **Edit files that build strings (JSON, HTML) with the file-edit tool.** A scripted regex or index-splice edit can build clean and break at runtime or delete a needed statement. Run the end-to-end smoke check before committing.
