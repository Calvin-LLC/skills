# Running the Phase C checkpoint

- **Plain technical language.** Name who writes what and when. No design-review vocabulary ("interface depth", "shape wins", "grafts", "seams", "blast radius") and no invented compound labels for mechanisms: a reader who was not in the design session must follow every sentence.
- **Questions are decision budget.** Spend them only inside the subsystem the user scoped. For a surface the user deprioritized, take the simplest honest default, state it in one line, and move on.
- **"Consult me as constraints arise" is a standing invitation, not a batch.** Ask the one fork that blocks the next phase, with a recommendation, then proceed; a form of several questions up front is the failure that instruction was meant to prevent.
