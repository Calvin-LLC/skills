# Reviewing a global steering file (SOUL.md and similar)

Use when the ask is "how has SOUL.md been working / what should change". The file loads in every workspace, so the per-repo export in the main workflow is the wrong sample. Measure across all workspaces.

1. **Find the live file and its mirror.** `git log --format='%h %ad %s' --date=short -- hermes~.md` gives the last change (the before/after cut-off). `diff ~/.hermes/SOUL.md hermes~.md` must be empty; edit both in the same step. Locate it with targeted paths (`ls ~/.hermes/SOUL.md hermes~.md`), never `find / -iname`. If a broad `find` is already running, kill it by PID: `pkill -f 'find / ...'` matches the invoking shell's own command line and terminates the tool call.
2. **Export what the user typed, across workspaces.** `session export --format jsonl --only user-prompts --after <date> --yes $TMPDIR/<dir>/up.jsonl` (rows: `session_id`, `created_at`, `text`). Drop `cron_*` sessions, texts under 20 chars, `[CONTEXT`/`[PRIOR` summaries, `Reply with exactly` probes, and pasted skill bodies (`[IMPORTANT: The user has invoked ...`); count those last ones separately as slash-skill invocations.
3. **Repeated typed instructions are the signal.** A rule the user re-types is either missing from the file or not reaching the agent. Cluster by regex (tests, docs, delete, waits, push, subagents, plain language), then read the actual prompts behind each top cluster; regex counts are upper bounds. Prompts in sessions with a `parent_session_id` are orchestrator briefs to subagents. A rule appended there by hand (for example "no new unit tests") proves it did not reach the child.
4. **Check delivery before judging wording.** `task` builds children with `skip_context_files=True`, and `_identity_parts` in `agent/system_prompt.py` loads SOUL only when `load_soul_identity` is set or context files are not skipped. Rules for delegated work therefore belong in the dispatch brief, not only in SOUL. `sessions.system_prompt` is null in the database, so confirm from the code path, not from stored prompts.
5. **Measure compliance from `state.db`** (open with `file:~/.hermes/state.db?mode=ro`). For a format rule, take assistant messages with no `tool_calls` that precede a user message (or end the session), with at least 3 tool results since the last user turn, and test them for the required headings. Split at the last-change timestamp. Report the count and which sessions missed. A format rule applies to every message, including mid-work status updates; the only exempt message is one whose main job is a question. Count a mid-work miss as a miss, not as an expected exception.
6. **Propose, then edit only what was approved.** State what is measured versus assumed.
