# Submodules and multi-repo trees

Read before committing or pushing in a repo that has submodules or gitlinks.

- **Push leaf repos first, then bump and push the parent.** A superproject stores a gitlink SHA; bumping it before the submodule's commit exists upstream points every clone at an object nobody can fetch.
- **Verify each repo against its own remote.** A clean parent says nothing about the submodule: run `git ls-remote origin refs/heads/main` per repo and compare to local `HEAD`. A dirty submodule and a moved pointer both render as `M <path>` in the parent's status; the parent's `git diff` tells them apart. A `-Subproject commit <sha>` / `+Subproject commit <sha>-dirty` pair is uncommitted work inside the child, not a pointer that moved, and it must be committed and pushed in the child before the parent's "clean" means anything.
- **A submodule checkout is normally detached, so `git push origin main` there sends the stale local `main` branch, not your commit.** `git status -sb` reads `## HEAD (no branch)`. Push the commit itself: `git push <remote> HEAD:main`. A `non-fast-forward` rejection while `git rev-list --left-right --count HEAD...origin/main` reports `1 0` is this trap: check for a detached HEAD before theorizing about the remote's state.
- **The submodule's `origin` is often a local working mirror, not the upstream named in `.gitmodules`.** It refuses pushes to its checked-out branch (`! [remote rejected] HEAD -> main (branch is currently checked out)`), and fast-forwarding that mirror in place is a detour, not the fix. Read `.gitmodules` for the real URL, add it as a named remote, fetch it, confirm the divergence is ahead-only before pushing, then `git push <remote> HEAD:main` and verify with `git ls-remote <remote> refs/heads/main`. Never force.
- **A gitlink whose `.gitmodules` URL is a local absolute path is unpushable**: no clone can resolve it. Either give that repo a real remote (push `main`, then point `.gitmodules` at it) or drop the gitlink and vendor the source. A private repo under the owner's own org is a reversible door worth taking without a question; a public one is not.
- **A tracked gitlink with no `.gitmodules` entry breaks every fresh clone** (`fatal: no submodule mapping found in .gitmodules for path ...`). Add the mapping in the same commit that touches submodules, and re-run `git submodule status` afterwards: it should list every path instead of dying.
- **Build output inside a submodule path is not parent cleanliness.** Ignore it in the owning repo rather than committing megabytes of binaries just to make `git status` quiet.
